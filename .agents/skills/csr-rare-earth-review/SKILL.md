# 稀土二次资源选择性回收综述

开始任务前读取项目根目录的 `PROJECT_DECISIONS.md`、`REVISION_LOG.md` 和 `memory/CODEX_LESSONS.md`。项目决策记录优先于临时建议；待确认内容不能写成定稿，已否定方案不能未经重新讨论恢复。

全文围绕“选择性如何形成、放大与保持”组织。资源赋存、浸出前固相调控、浸出与液相物种、选择性分离和产品化各自承担不同论证功能。第三章讨论浸出前固相状态调控；第四章讨论固液反应、元素释放和液相物种形成；第五章讨论利用化学差异实现分离；第六章讨论产品化、流程耦合、介质循环和选择性保持。

正文使用连续的综述段落。每段保留清晰中心论点，并把代表性案例、关键数据和证据边界连接到该论点。避免 PPT 提纲、流程图式箭头、概念伪公式和没有论证职责的技术罗列。保留真实资源案例和能够支撑机制判断的定量数据。

机制判断必须区分作者直接观察、作者解释和综述推断；区分真实废料与模型体系；不把浸出率提高、表征变化或最终产品纯度单独写成完整机制证明。优先使用高质量相关原始研究和权威综述，每条引文都要有明确论证职责。

## 原文保护与修改权限

根据用户要求选择最低级别：

- L0 精确替换：只改指定编号、DOI、作者、年份、公式或图表编号、术语、错别字、单位或符号。
- L1 局部语言修改：只改指定句子或局部表达，保留科学含义、数据、引文关系和段落结构。
- L2 段落论证修改：只改指定段落及用户明确授权的关联内容。
- L3 结构性修改：仅在用户明确授权时调整章节顺序、标题、案例组织或核心框架。

修改级别不得自行升级。执行 L0 时，冻结正文、标点、段落顺序、标题、数据、其他编号和文献顺序；修改后逐字符核对差异。执行 L1 或 L2 时分别逐句或逐段核对。无法取得完整当前原文时，不得凭记忆重建。

如果用户只要求提出建议，建议与替换稿分开；如果原文已经准确、清晰且论证完整，保留原文就是合格结果。修改记录写入 `REVISION_LOG.md`，新确认的项目决策写入 `PROJECT_DECISIONS.md`。

云端任务只能读取当前云端环境或已连接仓库中实际存在的项目文件。不要声称已加载本机用户级规则、Zotero 数据库、浏览器会话或其他本地文件。
